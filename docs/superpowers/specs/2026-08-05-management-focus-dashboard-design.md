# 个人管理重点看板设计

## 目标

在不替代公司项目管理平台的前提下，为个人工作台增加一个“重点关注”页面，帮助主管随时看清重点项目、负责人状态、需要本人处理的风险与下一步管理动作。

## 产品边界

- 公司平台继续保存正式项目、团队任务、工作日志、工时和交付资料。
- 个人工作台只保存简短管理摘要以及公司平台链接。
- 不在个人工作台保存详细技术参数、客户机密、员工敏感评价或指导计划原文。
- 不改变现有“今日、任务、记录、复盘、设置”的结构和业务逻辑，仅新增一个导航入口和一组独立数据。

## 页面结构

“重点关注”页面包含三个区域：

1. **重点项目**：显示项目状态、优先序列、负责人、本周目标、主要风险、本人下一步、最新结论、下次检查日期和公司平台链接。
2. **我的管理动作**：复用现有当天任务，不建立第二套任务系统。重点项目中的“本人下一步”可以一键加入今日任务。
3. **负责人检查**：从重点项目按负责人汇总，仅提示总体状态、需要支持的事项和最近检查日期，不管理每位员工的详细任务。

## 项目数据

每个重点项目包含：

- 名称；
- 公司平台链接，可留空；
- 负责人；
- 优先序列：前三优先、正常并行、明确暂缓；
- 状态：正常、需关注、已阻塞；
- 本周目标或当前节点；
- 最大风险或阻碍；
- 本人下一步管理动作；
- 最新结论；
- 下次检查日期；
- 创建及更新时间。

## 操作规则

- 支持新增、编辑和确认删除重点项目。
- 公司平台链接仅接受 `http://` 或 `https://` 地址；为空时不显示跳转按钮。
- “加入今日任务”会调用现有任务创建逻辑，以项目下一步作为标题，并在描述中注明关联项目；不会增加新的任务状态或改变任务列表逻辑。
- 负责人检查由项目数据即时计算，不增加独立负责人表，避免重复维护。
- 项目为空时显示用途说明和新增入口，不写入演示用公司数据。

## 存储与同步

- `Workspace` 增加 `focusProjects` 集合；旧本地数据缺少该字段时自动补为空数组。
- Supabase 增加 `focus_projects` 表、更新时间触发器、索引和仅本人可访问的 RLS 策略。
- 云端读取、保存、清空和 401 刷新重试继续使用现有仓库机制，只将新表加入现有流程。
- 数据导出继续导出完整 JSON，并在 Markdown 中增加“重点关注”章节。

## 兼容性与发布

- 保持 `schemaVersion: 1`，使用缺省字段兼容旧数据，避免破坏当前浏览器存储。
- 在发布新前端前先执行 Supabase 增量建表脚本，避免新页面上线时因表不存在导致云端读取失败。
- 保持 GitHub Pages、邮箱验证码登录和现有同步配置不变。

## 测试标准

- 旧本地数据加载后获得空的 `focusProjects`。
- Supabase 行数据能够与重点项目双向映射。
- 用户可以新增、编辑、删除重点项目，并将下一步加入今日任务。
- 原有导航、任务、记录、复盘、设置测试继续通过。
- 单元测试、ESLint、TypeScript 和生产构建全部通过后才能推送。
