# 周期任务设计

日期：2026-08-17

## 目标

为个人工作台增加一个独立的“周期”页面，用于管理需要按固定规律重复执行的工作和生活事项，例如每月还贷、每 5 天清理扫地机器人、每季度提交报告或每年办理续期。

周期计划负责定义“什么时候应当再做一次”，到期后生成一条普通日期任务。生成后的任务继续使用现有今日任务、待办、番茄钟和云端同步能力，避免另建一套执行系统。

第一版的核心目标是：

- 支持每 `N` 天、周、月、季度或年执行。
- 同时适应固定日期事项和完成后重新计时的维护事项。
- 到期后自动生成当天任务，并在工作台内提醒。
- 在 Mac、Win10 和 iPhone 登录同一账号时同步规则与结果，并防止重复生成。
- 保留每一期的独立执行记录，便于确认某一期是否完成。

## 产品原则

周期计划与执行任务分开保存：

- 周期计划是长期规则，例如“每月 15 日还房贷”。
- 周期实例是某一期应执行的普通任务，例如“2026 年 9 月 15 日还房贷”。
- 编辑某一期任务只影响这一期。
- 编辑周期计划只影响尚未生成的未来期次。
- 暂停或终止周期计划不删除已经生成的任务和历史记录。

不采用“完成后把同一条任务改到下一日期”的方式，因为它会丢失各期历史；也不提前批量生成大量未来任务，以免任务页堆积并增加修改规则时的清理风险。

## 导航与页面

### 主导航

在“今日、关注、任务、记录、复盘、设置”旁新增“周期”导航项。建议使用循环箭头或日历循环图标。

当存在今天新到期且尚未处理的周期事项时，“周期”导航显示数量。数字只表示需要关注的到期事项，不包含未来事项。

### 周期页结构

页面按以下顺序组织：

1. 页面标题与“新建周期”按钮。
2. 摘要区：今日到期、未来 7 天、已逾期、已暂停。
3. 状态筛选：进行中、已暂停、已终止、全部。
4. 周期计划列表。

每条周期计划至少显示：

- 名称和工作/生活分类。
- 周期文字，例如“每 2 周”或“每 4 月”。
- 计算基准：固定日期循环或完成后重新计时。
- 下一执行日期。
- 漏期处理方式；完成后重新计时的计划不显示此项。
- 状态：进行中、已暂停或已终止。
- 最近一期任务状态。
- 编辑、暂停/恢复、跳过本期和终止操作。

“终止”代替普通列表中的直接删除，避免历史周期来源断裂。第一版不提供永久删除含有生成记录的周期计划。

### 今日页与任务页

今日页顶部增加紧凑提示，例如“今天有 3 项周期任务”。点击后可以查看对应任务或进入周期页。

到期生成的任务出现在现有今日任务列表中，并显示“周期任务”标记。任务仍可：

- 标记完成或取消。
- 编辑本期标题、说明、日期和优先级。
- 使用番茄钟并累计专注时长。
- 手动顺延。
- 到日期结束仍未完成时，按现有规则自动进入待办，并标记“已部署但未执行”。

任务页不新增另一套周期任务列表。周期规则在“周期”页管理，具体执行仍在“今日”和“任务”中完成。

## 新建与编辑周期

表单字段如下：

- 名称：必填。
- 说明：可选，生成任务时复制为任务说明。
- 分类：工作或生活。
- 首次执行日期：必填，也是固定循环的计算锚点。
- 周期数字：正整数，默认 `1`。
- 周期单位：天、周、月、季度、年。
- 计算基准：固定日期循环、完成后重新计时。
- 漏期处理：每期都要补、只保留最近一期。仅固定日期循环可选。
- 任务优先级：高、中、低，生成任务时使用。
- 页面提醒：默认开启。
- 浏览器通知：默认关闭，由用户主动开启并授权。
- 结束日期：可选；到达结束日期后不再生成新任务。

表单直接显示自然语言摘要，例如：

> 从 2026 年 8 月 20 日开始，每 2 周生成一次；按固定日期循环；漏期时每期都补。

这段摘要随输入即时更新，用于在保存前发现配置错误。

## 周期计算规则

所有日期计算使用工作台个人设置中的时区，以自然日为单位，不使用设备当前时区直接替代。

### 每 N 天

从首次执行日期或上次完成日期起，每隔 `N` 个自然日到期。

### 每 N 周

以首次执行日期的星期几为准，每隔 `N` 周到期。例如首次日期为周二，“每 2 周”始终落在对应周期的周二。

### 每 N 月

沿用计算锚点的日号。如果目标月份没有该日，则使用当月最后一天。例如以 31 日为锚点时，二月落在 28 日或 29 日，下一次仍按原始锚点 31 日计算，不能永久变成 28 日。

### 每 N 季度

等同于每 `3 × N` 个月，并沿用月份规则。例如“每 2 季度”即每 6 个月。

### 每 N 年

沿用锚点的月和日。2 月 29 日遇非闰年时落在 2 月最后一天，下一闰年仍恢复为 2 月 29 日。

### 固定日期循环

下一期始终依据原始计划表计算，不受上一期实际完成时间影响，适用于还贷、例会、月报等事项。

漏期处理有两种：

- 每期都要补：重新打开工作台时，为每个尚未生成的到期日分别生成任务。
- 只保留最近一期：只生成不晚于今天的最近一期，较早漏期记为已略过，不生成多条任务。

固定循环允许前一期尚未完成时生成下一期。不同期次通过应执行日期区分。

### 完成后重新计时

当前一期完成后，以实际完成日期作为新锚点，再计算下一执行日期，适用于清理、保养、维护等事项。

该模式同一时间只保留一个有效期次。当前一期未完成时不生成下一期，因此不提供漏期处理选项。若本期被取消或通过周期页“跳过本期”，以操作当天作为新的计算锚点，避免计划永久停止。

### 结束日期

候选执行日期晚于结束日期时不再生成任务，并将计划显示为“已结束”。结束日期当天仍可生成一期。

## 自动生成流程

工作台在以下时机检查周期计划：

- 完成工作区与云端数据加载后。
- 页面刷新后。
- 浏览器标签重新获得焦点后。
- 新建、修改、暂停或恢复周期计划后。
- 完成、取消或跳过“完成后重新计时”的当前一期后。

检查流程：

1. 读取当前用户时区中的今天。
2. 筛选进行中且未超过结束日期的周期计划。
3. 按计划模式计算应生成的期次。
4. 使用“周期计划 ID + 本期应执行日期”检查是否已经生成。
5. 仅为缺失期次创建任务，并保存期次来源。
6. 云端发生重复写入冲突时，将其视为另一设备已经完成生成，重新读取数据，不向用户报错。
7. 更新周期计划的下一执行日期和页面提醒状态。

网页无法在完全关闭时运行代码。因此“到期自动生成”的准确含义是：网页正在运行时到期即检查；网页关闭期间到期，则在下一次打开或恢复页面时立即补建。

## 生成任务的行为

生成任务沿用现有 `WorkspaceTask`，并增加周期来源信息：

- `recurringPlanId`：来源周期计划 ID，普通任务为空。
- `recurrenceDueDate`：本期原定执行日期，普通任务为空。
- `source` 增加 `recurring_plan`。

生成时：

- `taskDate` 等于本期应执行日期；若采用“只保留最近一期”并在晚于应执行日时补建，仍保留原定日期，使其按现有过期规则进入“已部署但未执行”。
- 标题、说明和优先级从周期计划复制。
- 状态为“未开始”。
- 归类为普通日期任务。

用户修改生成任务后不回写周期计划。周期计划改名后，既有历史任务标题不变，未来任务使用新名称。

用户删除某一期任务时，只删除该任务。系统保留该期已经生成过的记录，不会因下一次检查而重新创建，除非用户在周期页明确选择“重新生成本期”。

## 提醒设计

### 页面提醒

页面提醒默认开启，不依赖浏览器权限：

- 今日页显示当天新到期数量。
- 周期导航显示需要关注的数量。
- 周期页区分今日到期、未来 7 天和已逾期。
- 生成任务显示“周期任务”标记。

“已逾期”依据尚未完成或取消的周期任务计算。任务自动进入待办后，周期页仍可显示其未执行状态并跳转到对应待办。

### 浏览器通知

浏览器通知为每台设备独立设置：

- 用户主动开启时才申请通知权限，不在首次访问时弹出。
- 网页正在运行或重新进入时，对新到期事项发送一次通知。
- 同一设备、同一周期、同一期只通知一次。
- 权限被拒绝、浏览器不支持或系统限制通知时，只停用系统通知；任务生成、页面提醒和云同步继续工作。
- 通知权限和“本设备已通知”记录保存在设备本地，不同步到 Supabase。

第一版不承诺网页完全关闭后的通知。要实现可靠的后台邮件、短信或推送，需要独立定时服务，留作后续功能。

## 状态与操作

周期计划状态：

- `active`：正常检查并生成任务。
- `paused`：暂不生成，保留规则与历史。
- `terminated`：永久停止生成，保留历史，只允许查看或复制为新计划。
- `ended`：已超过结束日期，由系统自动判定。

操作规则：

- 暂停：不生成暂停期间的任务。
- 恢复固定循环：按所选漏期规则处理暂停期间已经到期的期次。
- 恢复完成后循环：若已有未关闭实例则继续等待，否则从恢复当天重新计算下一期。
- 跳过本期：记录本期已跳过，不生成或关闭对应任务；固定循环继续原计划，完成后循环从跳过当天重新计时。
- 终止：二次确认后停止未来生成，既有任务与历史保留。

## 数据模型

### 周期计划

新增 `RecurringPlan`：

```ts
type RecurrenceUnit = "day" | "week" | "month" | "quarter" | "year";
type RecurrenceMode = "fixed" | "after_completion";
type MissedOccurrencePolicy = "catch_up_all" | "latest_only";
type RecurringPlanStatus = "active" | "paused" | "terminated";

interface RecurringPlan {
  id: string;
  title: string;
  description: string;
  category: "work" | "life";
  startDate: string;
  interval: number;
  unit: RecurrenceUnit;
  mode: RecurrenceMode;
  missedPolicy: MissedOccurrencePolicy | null;
  priority: TaskPriority;
  inAppReminder: boolean;
  browserNotification: boolean;
  endDate: string | null;
  status: RecurringPlanStatus;
  completionAnchorDate: string | null;
  nextDueDate: string | null;
  createdAt: string;
  updatedAt: string;
}
```

`interval` 必须为正整数。`after_completion` 的 `missedPolicy` 必须为空；`fixed` 的 `completionAnchorDate` 必须为空。计划终止或超过结束日期且不再有候选期次时，`nextDueDate` 为 `null`；页面据此显示“已结束”，不把“已结束”写成可被用户修改的持久状态。

### 期次记录

仅依赖任务是否存在无法区分“从未生成”和“生成后被用户删除”。因此新增轻量的 `RecurringOccurrence`：

```ts
type RecurringOccurrenceStatus = "generated" | "completed" | "cancelled" | "skipped" | "deleted";

interface RecurringOccurrence {
  id: string;
  recurringPlanId: string;
  dueDate: string;
  taskId: string | null;
  status: RecurringOccurrenceStatus;
  resolvedAt: string | null;
  createdAt: string;
  updatedAt: string;
}
```

期次记录保证同一期不会因任务删除、页面刷新或多设备同时打开而重新生成。

### 工作区版本

`Workspace` 增加 `recurringPlans` 与 `recurringOccurrences`，并将 schema 版本从 `2` 升级到 `3`。读取旧版数据时补充两个空集合，不改变现有任务、待办、番茄钟和记录。

## Supabase 与跨设备同步

新增：

- `recurring_plans` 表，保存周期规则。
- `recurring_occurrences` 表，保存每一期生成与处理结果。
- `tasks` 表增加 `recurring_plan_id` 与 `recurrence_due_date`。

云端约束：

- 所有表继续使用 `user_id` 隔离数据并启用 RLS。
- `(user_id, recurring_plan_id, due_date)` 设置唯一约束，防止多设备重复生成同一期。
- 期次删除计划时使用级联删除只适用于尚无历史的草稿；正式计划采用终止状态，不物理删除。
- 任务删除时将期次的 `task_id` 置空并把状态改为 `deleted`，不删除期次记录。
- 周期计划、期次与任务写入应作为一个可重试操作；发生唯一约束冲突时重新拉取云端数据。

本地模式使用相同的数据结构和生成算法。切换到云端模式时沿用现有工作区同步流程，不把浏览器通知权限或本设备通知记录上传。

## 错误与边界处理

- 周期数字为空、非整数或小于 1 时禁止保存。
- 结束日期早于首次执行日期时禁止保存。
- 修改计划时若新的下一执行日期早于今天，保存前明确显示将按哪种漏期规则生成。
- 设备时间或时区变化时，以工作台设置时区重新计算日期，不重复创建已经存在的期次。
- 云端暂时不可用时显示保存失败，不在只保存了一半规则时假装成功。
- 多设备并发生成同一期时，唯一约束决定唯一结果，冲突设备重新加载。
- 补建大量历史期次时分批处理并显示数量确认，避免一次生成大量任务导致页面卡顿。第一版单次自动补建上限为 100 条；超过时暂停并提示用户确认继续。
- 月底和闰年计算始终保留原始锚点，不能把临时落在月末的日期当成新的永久日号。
- 已终止计划不能恢复；需要时可复制为新计划。

## 导出

- JSON 导出包含周期计划、期次记录和任务周期来源字段。
- Markdown 导出增加“周期计划”章节，列出名称、周期、状态、下一执行日期和最近一期结果。
- 浏览器通知权限与本设备已通知记录不导出。

## 测试与验收

### 周期算法

- 每 `N` 天、周、月、季度、年计算正确。
- 每月 29、30、31 日在短月份正确落到月末，后续恢复原始日号。
- 2 月 29 日跨闰年计算正确。
- 工作台时区与设备时区不同时仍在正确自然日生成。
- 固定循环不受实际完成日期影响。
- 完成后循环以完成或跳过日期重新计算。

### 生成与状态

- 到期只生成一条普通日期任务和一条期次记录。
- 每期都补与只保留最近一期符合各自规则。
- 暂停期间不生成，恢复后正确处理漏期。
- 终止和结束日期之后不生成。
- 编辑或删除单期任务不改变周期规则，也不会自动复活已删除期次。
- 周期任务可正常完成、取消、顺延、进入待办和使用番茄钟。

### 同步与并发

- Mac、Win10 与 iPhone 登录同一账号后看到相同周期计划、下一日期和期次状态。
- 两台设备同时打开时，同一期云端只存在一条任务和一条期次记录。
- 云端保存失败时不产生规则、期次和任务互相矛盾的半完成状态。
- 本地 Workspace v2 与现有 Supabase 数据升级后保持原有任务和专注记录不变。

### 页面与提醒

- 今日提示、导航数量和周期页摘要与真实任务状态一致。
- 浏览器通知只在授权后触发，同一设备同一期只触发一次。
- 通知不可用时不影响任务生成和页面提醒。
- 桌面、常见 Win10 浏览器宽度和 390px 手机宽度无横向溢出或操作遮挡。
- 现有今日、关注、任务、待办、记录、复盘、设置和番茄钟流程不回归。

## 第一版不包含

- 网页关闭后的邮件、短信或可靠后台推送。
- 精确到小时和分钟的后台提醒。
- 法定节假日、仅工作日或调休规则。
- 农历周期。
- 一个计划同时选择多个星期几。
- 外部日历、公司项目平台或第三方任务系统同步。
- 复杂统计报表和完成率趋势图。
