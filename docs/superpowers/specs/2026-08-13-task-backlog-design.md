# 待办任务设计

## 目标

在不改变现有主导航和当日任务工作流的前提下，提供一个用于管理近期但尚未确定执行日期事项的待办视图。同时，任何当天未完成的日期任务都应在当天结束后自动进入待办，避免它们继续停留在已过日期中。

## 范围

- 任务页增加“日期任务”和“待办任务”两个页签。
- 新建任务默认安排到当天，并可主动选择“创建为待办”。
- 自动将过期且未完成的日期任务转入待办。
- 待办任务可重新安排到指定日期，并立即恢复为普通日期任务。
- 待办状态保存到本地和 Supabase，且与既有数据兼容。

不包含独立待办导航、提醒通知、待办排序、批量排期、跨设备计时续接或番茄钟对待办的直接支持。

## 数据模型

`WorkspaceTask` 增加以下字段：

- `placement`：`scheduled`、`backlog`。默认 `scheduled`，旧数据迁移后也为 `scheduled`。
- `backlogKind`：`unscheduled`、`unexecuted` 或 `null`。
- `originalTaskDate`：`string | null`。仅当自动转入待办时记录原计划日期。

`scheduled` 任务必须有当前执行日期，并且 `backlogKind` 和 `originalTaskDate` 为 `null`。`backlog` 任务不参与日期任务、今日任务或番茄钟选择。

## 创建与安排

新建任务表单默认填写当天日期。表单提供“创建为待办”复选框：

- 未勾选：创建普通日期任务，沿用填写的日期。
- 勾选：创建 `backlog / unscheduled` 任务，日期输入不可编辑或隐藏，不记录原计划日期。

待办页中的每项任务提供“安排日期”操作。用户选定并保存日期后，任务切换为 `scheduled`，清除 `backlogKind` 与 `originalTaskDate`，立即从待办页移到对应日期的任务列表。

## 自动转入规则

应用完成工作区加载、云端同步完成、任务页打开或页面重新获得焦点时，检查任务：

- `placement` 为 `scheduled`；
- `taskDate` 早于用户时区中的今天；
- 状态为 `todo` 或 `doing`。

符合条件的任务自动切换为 `backlog / unexecuted`，并将原 `taskDate` 保存到 `originalTaskDate`。`done` 和 `cancelled` 任务不转入待办。

该操作必须幂等：重复检查不能覆盖首次记录的原计划日期，也不能重复保存或生成副本。因为网页在用户下一次打开、刷新或重新聚焦时才有机会运行代码，“当天结束后自动转入”在产品上表现为下一次应用可运行时立即完成。

手动“顺延”继续沿用当前含义：直接修改为明天的普通日期任务，不产生“已部署但未执行”标记。

## 页面与标记

任务页顶部页签：

- “日期任务”：保留当前日期选择、状态筛选、任务列表和新建任务入口。
- “待办任务”：显示所有未完成、未取消的 `backlog` 任务，分为“尚未安排日期”和“已部署但未执行”两个组。

自动转入的项目显示醒目的文字标记“已部署但未执行”，并显示“原计划：YYYY年M月D日”。主动创建的项目显示“待排期”。待办页不显示已经完成或已取消任务。

任务详情、编辑、完成、取消、删除和专注时长展示保持既有逻辑。正在番茄钟中的任务继续不可删除；待办任务不会进入今天的番茄钟选择列表。

## 同步与迁移

本地仓库迁移为新任务字段填充安全默认值。Supabase 的 `tasks` 表增加对应列、约束检查和同步映射；现有云端记录以普通日期任务读取。自动转入产生的任务更新通过现有工作区保存路径同步，遵循已有 RLS 规则。

## 测试

- 旧版本本地和云端任务在迁移后保持为普通日期任务。
- 主动创建待办任务，默认不进入今日任务或番茄钟。
- 过期未完成任务自动转为 `unexecuted`，首次原计划日期保持不变。
- 已完成、已取消和手动顺延任务不被自动转入。
- 待办重新安排日期后回到日期任务并清除待办标记。
- 任务页页签和手机布局可用，现有任务、番茄钟与同步测试不回归。
