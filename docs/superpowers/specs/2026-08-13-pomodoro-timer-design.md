# 番茄钟设计

日期：2026-08-13

## 目标

在不改变个人工作台现有导航、任务管理和跨设备同步逻辑的前提下，为“今日工作台”增加一个与今日任务关联的番茄钟。用户完成一次专注后，系统将该次时长记录到所选任务，并展示今日专注合计与任务累计专注时长。

第一版优先保证计时可靠、数据可追溯和手机端易用，不建设独立统计中心。

## 已确认的使用规则

- 番茄钟嵌入“今日工作台”，不增加新的导航项。
- 只能选择今天状态为“未开始”或“进行中”的任务。
- 默认 25 分钟，可选择 15、25、45 或 60 分钟。
- 开始番茄钟时，所选任务若为“未开始”，自动更新为“进行中”。
- 允许暂停与继续；暂停期间不计入倒计时。
- 主动放弃后，整次番茄钟不产生专注记录，也不计入任务时长。
- 倒计时归零后进入等待确认状态。只有用户点击“完成并计入”才保存记录。
- 完成时显示页面提示并播放提示音；用户已授权浏览器通知时，同时发送系统通知。
- 第一版不提供休息倒计时。
- 每台设备独立维护正在进行的计时，不跨设备接续或抢占。
- 完成后的专注记录参与本地持久化或 Supabase 云同步。

## 页面与交互

### 页面位置

在“今日最重要”区域与“今日任务”区域之间增加紧凑的专注计时区，保持当前今日页的阅读顺序：

1. 今日标题与同步状态
2. 今日最重要
3. 专注计时
4. 今日任务
5. 快速记录
6. 每日复盘入口

计时区包含：

- 今日已完成番茄数量与今日专注总分钟数
- 今日有效任务选择器
- 15 / 25 / 45 / 60 分钟分段选择
- 剩余时间
- 与当前状态匹配的开始、暂停、继续、放弃或完成按钮

每条任务在现有状态和优先级信息附近显示该任务的累计专注时长。没有专注记录的任务不显示 `0 分钟`，避免增加噪声。

### 计时状态

计时器包含以下状态：

1. `idle`：选择任务与分钟数，可以开始。
2. `running`：根据结束时间显示剩余时间，可以暂停或放弃。
3. `paused`：保存剩余毫秒数，不继续倒计时，可以继续或放弃。
4. `awaiting_confirmation`：计时已归零，等待用户完成并计入或放弃。
5. `saving`：正在保存已完成的专注记录，防止重复提交。

同一设备同时只能存在一个未结束的番茄钟。开始新计时前，必须完成或放弃当前计时。

### 关闭网页与锁屏

计时过程不依赖 JavaScript 定时器持续运行。`running` 状态保存绝对结束时间，页面显示的剩余时间始终通过当前时间与结束时间之差计算。

- 重新打开时尚未到点：恢复 `running` 并显示正确剩余时间。
- 重新打开时已经到点：进入 `awaiting_confirmation`，不自动保存记录。
- 关闭网页时处于暂停状态：恢复 `paused`，剩余时间保持不变。

## 数据设计

### 已完成专注记录

在 `Workspace` 中新增 `focusSessions` 集合，并将 `schemaVersion` 从 1 升级到 2。新增 `FocusSession`：

```ts
interface FocusSession {
  id: string;
  taskId: string | null;
  taskTitle: string;
  focusDate: string;
  plannedMinutes: 15 | 25 | 45 | 60;
  completedAt: string;
  createdAt: string;
}
```

`taskTitle` 是完成时的标题快照。任务后来改名或删除时，历史记录仍能说明当时的投入对象。

`taskId` 可以为空。正常完成时记录所选任务 ID；如果计时期间任务已在其他设备被删除，则保存记录时将任务 ID 置空并保留标题快照。若任务仅被取消，仍允许完成当前计时并保留关联。

任务累计专注时长由所有 `taskId` 匹配的专注记录求和。今日统计由 `focusDate` 匹配当前工作台日期的记录求和，不在任务上维护可被并发覆盖的累计字段。

### 当前设备计时状态

正在进行的计时使用独立的、带版本号的 `localStorage` 键保存，不放入 `Workspace`，不进入 Supabase，也不导出：

```ts
interface LocalPomodoroState {
  version: 1;
  status: "running" | "paused" | "awaiting_confirmation";
  taskId: string;
  taskTitle: string;
  plannedMinutes: 15 | 25 | 45 | 60;
  startedAt: string;
  endsAt: string | null;
  remainingMs: number | null;
}
```

这样可以满足“每台设备独立计时”，同时让已完成结果通过现有账号同步。

### Supabase

新增 `focus_sessions` 表：

- `id uuid primary key`
- `user_id uuid not null references auth.users(id) on delete cascade`
- `task_id uuid null`
- `task_title text not null`
- `focus_date date not null`
- `planned_minutes smallint not null`，限制为 15、25、45 或 60
- `completed_at timestamptz not null`
- `created_at timestamptz not null default now()`

`task_id` 单独引用任务主键并设置 `on delete set null`。删除任务时只清空任务关联，不影响专注记录中不可为空的 `user_id`。增加 `(user_id, focus_date)` 和 `(user_id, task_id)` 索引。

启用 RLS，并沿用现有表策略：登录用户只能查询、新增、更新和删除自己的记录。

## 数据兼容与同步

- 读取旧版 `schemaVersion: 1` 数据时，自动补充 `focusSessions: []` 并升级为版本 2。
- 本地仓库继续整体保存 Workspace。
- Supabase 仓库增加 `focus_sessions` 的读取、增量同步与清理，不改变现有表的同步语义。
- 专注记录保存成功后，再更新页面汇总。
- 云端保存失败时，保留一份待提交的完成记录和错误提示，用户可重试；在成功前禁用重复的“完成并计入”。
- 不同步 `running`、`paused` 或 `awaiting_confirmation` 状态。

## 提醒与权限

- 页面内完成提示始终可用。
- 提示音由浏览器端内置短音频或 Web Audio 播放，不依赖外部资源。
- 仅在用户主动开始计时的交互过程中申请通知权限，不在首次打开页面时弹出权限请求。
- 权限被拒绝或浏览器不支持通知时，继续使用页面提示和提示音，不视为错误。
- 移动浏览器可能限制后台声音和通知；重新回到页面时仍会进入等待确认状态，因此不会丢失结果。

## 导出

- JSON 导出自然包含 `focusSessions`。
- Markdown 增加“专注记录”章节，按日期列出任务标题与分钟数，并提供每日合计。
- 当前设备尚未完成的倒计时不导出。

## 错误与边界处理

- 今日没有有效任务时，计时区显示空状态并提供“添加任务”入口。
- 计时开始后，任务选择和时长选择锁定，避免计时中途改变归属。
- 当前任务在本设备被删除时，先要求用户放弃或完成当前计时，再执行删除，避免意外丢失关联。
- 当前任务被其他设备删除时，完成记录仍保存标题快照，并将 `taskId` 置空。
- 重复点击、页面恢复和 React 重渲染不得生成重复专注记录；保存使用稳定的会话 ID 并保持幂等。
- 浏览器时间发生变化时，以存储的绝对结束时间重新计算；检测到明显倒拨时不自动判定完成，继续显示可恢复状态。
- 本地计时状态损坏或版本未知时，安全清除该状态，不影响 Workspace 数据。

## 测试范围

### 领域与数据测试

- 15 / 25 / 45 / 60 分钟合法值验证。
- Workspace v1 到 v2 的兼容升级。
- 今日专注合计、番茄数量和任务累计时长选择器。
- JSON 与 Markdown 导出。
- 本地仓库保存和恢复专注记录。
- Supabase 行映射、读取、保存、删除与任务删除后的空关联。

### 计时器测试

- 开始时将未开始任务更新为进行中。
- 暂停期间不减少剩余时间，继续后使用新的结束时间。
- 页面重新加载后按绝对时间恢复。
- 归零只进入等待确认，不自动产生记录。
- 完成并计入只保存一次。
- 放弃不产生记录。
- 无通知权限时正常完成。
- 保存失败后保留并成功重试。

### 界面与回归测试

- 今日页可选择且只列出今日未完成、未取消任务。
- 计时状态下按钮、字段锁定和提醒文案正确。
- 今日统计与任务累计时长随保存更新。
- 桌面、常见 Win10 浏览器宽度和 390px 手机宽度无横向溢出或内容遮挡。
- 原有任务新增、编辑、完成、取消、删除、顺延，以及记录、复盘、重点关注和同步流程保持正常。

## 第一版不包含

- 休息倒计时或长休息规则
- 自由输入计时分钟数
- 周报、月报、趋势图或排行榜
- 跨设备查看、接续或控制正在运行的计时器
- 自动判定任务完成
- 与 AI 每日总结联动
