# 个人工作台 MVP 设计规格

## 1. 目标与边界

构建一个可立即在本地浏览器运行的个人工作台，帮助用户完成每日计划、任务管理、工作记录、学习记录和晚间复盘。首版完整覆盖今日、任务、记录、复盘、历史筛选和设置/导出。

当前版本采用本地优先数据模式，不依赖 Supabase 凭据即可使用。项目同时保留明确的数据仓库边界，并提供 Supabase 数据库与 RLS 脚本，便于后续接入真实账户和跨设备同步。

本地版本明确不声称支持真实邮箱登录、用户隔离或跨设备同步。AI 总结、团队协作、第三方连接器和复杂统计不在本轮范围内。

## 2. 技术方案

- 应用框架：Next.js、React、TypeScript；
- 样式：Tailwind CSS，辅以少量全局设计变量；
- 图标：Lucide React；
- 数据访问：统一的 `WorkspaceRepository` 接口；
- 当前持久化：浏览器 `localStorage`；
- 后续持久化：Supabase Repository 适配器；
- 数据库交付：Supabase PostgreSQL 建表、索引、约束、触发器和 RLS 策略 SQL；
- 测试：Vitest 与 Testing Library；
- 浏览器验收：Playwright 桌面与移动视口。

选择 Next.js 而不是 Vite，是为了保持与最终 Vercel 部署和后续服务端 AI API 的架构一致。选择本地 Repository 而不是直接依赖 Supabase，是为了保证没有远端凭据时仍能完成和验证全部核心交互。

## 3. 信息架构

### 3.1 全局布局

桌面端使用窄侧栏和主内容区。侧栏包含产品名称、今日日期、今日、任务、记录、复盘和设置入口。移动端采用单列内容，底部固定主要导航，设置从顶部菜单进入。

所有页面使用一致的最大内容宽度、标题层级、操作位置和反馈样式。移动端不显示表格，不产生横向滚动。

### 3.2 今日页

今日页采用“专注单流”结构，按以下顺序呈现：

1. 日期、问候和保存状态；
2. 今日最重要的 1 至 3 件事；
3. 今日任务与完成度；
4. 工作和学习快速记录入口；
5. 情绪与精力状态；
6. 晚间复盘入口和当日摘要。

统计只作为次要反馈，不展示复杂指标卡或数据大屏。

### 3.3 任务页

任务支持新增、编辑、完成、取消、删除、按日期和状态筛选，以及将未完成任务顺延到下一天。任务字段包括标题、描述、日期、优先级、状态、来源和时间戳。

### 3.4 记录页

工作记录和学习记录共享页面骨架，通过分段控件切换类型。工作记录包括标题、内容、结果、关联任务和标签；学习记录包括标题、内容、来源链接、关键要点、下一步行动和日期。

页面支持关键词、日期和标签筛选。新增和编辑使用响应式抽屉或模态表单。

### 3.5 复盘页

复盘表单保持短小，包含完成事项、主要收获、阻碍、改进、明日重点、情绪、精力和备注。每个日期最多保存一条复盘。保存后显示摘要，历史区域按日期排列。

### 3.6 设置页

设置页显示本地模式说明、时区设置、示例数据状态、JSON/Markdown 导出，以及清空本地数据入口。清空操作必须二次确认。

## 4. 组件边界

- `AppShell`：负责桌面侧栏、移动底栏和主内容布局；
- `PageHeader`：统一页面标题、日期和主要操作；
- `SaveStatus`：展示保存中、已保存和保存失败；
- `TaskList` / `TaskForm`：任务展示与编辑；
- `RecordList` / `WorkEntryForm` / `LearningEntryForm`：记录展示与编辑；
- `ReviewForm` / `ReviewSummary`：复盘编辑与摘要；
- `FilterBar`：日期、状态、关键词和标签筛选；
- `ConfirmDialog`：删除与清空确认；
- `WorkspaceProvider`：加载仓库状态，暴露业务操作和保存状态；
- `WorkspaceRepository`：定义数据读取、写入、迁移和导出所需接口；
- `LocalWorkspaceRepository`：实现带版本的数据序列化和本地持久化。

组件通过类型明确的属性和 Provider 操作通信，不直接访问 `localStorage`。这样可以在不改动页面组件的情况下替换为 Supabase 实现。

## 5. 数据设计

本地根对象包含 `schemaVersion`、`profile`、`tasks`、`workEntries`、`learningEntries` 和 `dailyReviews`。所有业务实体使用 UUID、ISO 8601 时间戳和 `YYYY-MM-DD` 日历日期。

日期计算使用个人设置中的时区，默认 `Asia/Shanghai`。每个日期最多一条复盘；Repository 写入时执行该约束。

首次打开且没有本地数据时写入少量示例内容，帮助用户理解操作。设置页可以清空示例并重新开始。

Supabase SQL 使用与本地模型对应的 `profiles`、`tasks`、`work_entries`、`learning_entries` 和 `daily_reviews` 表。所有业务表启用 RLS，并限制 `auth.uid() = user_id`。复盘表对 `(user_id, review_date)` 添加唯一约束。

## 6. 数据流与交互

应用启动时，`WorkspaceProvider` 从 Repository 加载数据并完成版本迁移。页面从 Provider 读取派生视图，例如今日任务、完成度、筛选结果和连续复盘天数。

用户提交表单时，界面先进入“保存中”，Repository 完成写入后更新内存状态并显示“已保存”。若序列化或浏览器存储失败，界面显示“保存失败”，保持表单内容和当前页面状态，允许用户重试。

任务顺延会复制或更新日期，并保留来源信息与更新时间。删除操作必须经过确认。导出操作从完整工作区快照生成 JSON 或 Markdown 文件，不修改原数据。

## 7. 视觉与响应式

整体采用安静、工作导向的中性色界面，以绿色表示完成或良好状态，以琥珀色表示提醒，以红色表示危险操作。颜色不作为唯一状态线索，始终配合文本或图标。

界面使用紧凑但可读的排版、低圆角、细分隔线和有限阴影。卡片只用于独立重复项或必要的表单容器，不嵌套卡片。按钮使用 Lucide 图标与明确标签；图标按钮提供辅助文本。

断点下侧栏切换为底部导航，双列内容改为单列，抽屉占据适合拇指操作的区域。固定格式控件定义稳定尺寸，所有文本可以换行且不得溢出。

## 8. 错误处理与隐私

- 本地存储不可用或配额不足时显示可操作错误，不清空输入；
- URL、标签和必填字段在提交前校验；
- 删除记录和清空数据要求二次确认；
- 导出只在浏览器中生成，不上传数据；
- 本地模式提示数据仅保存在当前浏览器；
- Supabase SQL 不包含 service role key 或任何真实凭据；
- 未来接入远端时，敏感密钥只能存在于服务端环境变量。

## 9. 测试与验收

单元测试覆盖：

- Repository 初始化、读写和版本迁移；
- 任务新增、编辑、状态变更、删除和顺延；
- 工作记录、学习记录和复盘的增删改；
- 日期、关键词、状态和标签筛选；
- 完成度、连续复盘等派生计算；
- JSON 与 Markdown 导出。

组件测试覆盖关键表单校验、删除确认和失败时保留输入。Playwright 验收覆盖桌面和 iPhone 视口，包括页面导航、创建任务、完成任务、添加两类记录、保存复盘、刷新后数据仍存在、导出入口可用和页面无横向溢出。

完成标准是：无需远端凭据即可启动并完成完整核心流程；生产构建和自动测试通过；桌面与手机布局清晰无重叠；Supabase SQL 可供后续配置使用；界面对本地模式限制表述准确。

## 10. 后续演进

接入 Supabase 时新增 `SupabaseWorkspaceRepository` 和认证保护层，保留现有页面及业务组件。登录后可提供一次性本地数据迁移选择。跨设备同步、账户删除和真实用户隔离必须在 Supabase 环境中单独验收。

AI 日报仅在核心云端数据流程稳定后增加，通过 Next.js 服务端路由调用，并要求用户确认后才写入正式记录。
